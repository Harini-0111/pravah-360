## 2. Detailed Claim Reconciliations

### 2.1 Item 1: Spatial Holdout Validation Engine

- **Original Claim:**
  > *"Machine Learning model (Random Forest v2.1) evaluated on an independent spatial holdout partition (4 coastal delta mandals: Razole, Sakhinetipalli, Mummidivaram, Amalapuram). POD: 0.857, FAR: 0.0, IoU: 0.857... ground-truthed against CWC river gauge records."*
- **Verified Implementation Evidence:**
  1. File: `backend/app/services/prediction_validation_service.py`, lines 67–134.
  2. The function `_generate_synthetic_benchmark_dataset()` creates all training and testing samples programmatically using `np.random.seed(42)`.
  3. The target classification label `y` is calculated from a synthetic latent variable formula:
     ```python
     inundation_latent = (
         0.25 * (rf_72 / 300.0) +
         0.30 * max(0.0, gauge_ratio - 0.85) / 0.5 +
         0.20 * elev_factor +
         0.15 * dist_factor +
         0.10 * runoff +
         np.random.normal(0, 0.06)
     )
     y = 1 if inundation_latent > 0.52 else 0
     ```
  4. The features `elev_factor`, `dist_factor`, and `runoff` are drawn directly from `MANDAL_ENVIRONMENTAL_PROFILES`, which are the exact same physical parameters (elevation, river distance, land cover) used by the AHP susceptibility model.
  5. While `sar_candidate_pct` is included as a feature in the training matrix, `y` is **not** determined by Sentinel-1 SAR water masks or by field-surveyed inundation extents.
  6. The 4 coastal mandals are indeed held out from `X_train` during training and used for `X_test`, but the test samples are generated using the exact same synthetic formula.
- **Evidence File Paths:**
  - `backend/app/services/prediction_validation_service.py` (Lines 67–134, 180–200)
  - `docs/evidence_reconciliation.md` (Lines 141–185)
- **Status:** `PARTIAL` (Spatial holdout architecture is valid; claim that it uses observed ground truth is incorrect).
- **Corrected Interpretation:**
  The evaluation is an internal **Synthetic Multi-Scenario Spatial-Holdout Benchmark** designed to test whether a Random Forest classifier can generalize across held-out delta mandals without spatial overfitting. The metrics ($POD = 0.857$, $FAR = 0.0$, $IoU = 0.857$) evaluate learning consistency against a synthetic multi-criteria latent function, **not** against empirical field observations or independent satellite ground truth.

### 2.2 Item 2: Population Exposure & Demographic Composition

- **Original Claim:**
  > *"8.25 Million residing within elevated susceptibility zones (Moderate, High, and Very High risk tiers) across the Lower Godavari Basin."*
- **Verified Implementation Evidence:**
  1. Authoritative zonal summation on `data/processed/population/worldpop_lower_godavari_2020.tif` clipped to the 21 mandal boundaries in `data/processed/boundaries/lower_godavari_mandals.geojson` yields:
     - **Baseline Total Population:** $9,126,353$ persons ($100.00\%$) (or $9,126,355$ with per-pixel rounding).
     - **Very High Susceptibility ($\ge 0.72$):** $6,027,704$ persons ($66.05\%$).
     - **High Susceptibility ($0.58 - 0.72$):** $2,225,020$ persons ($24.38\%$).
     - **Moderate Susceptibility ($0.44 - 0.58$):** $663,126$ persons ($7.27\%$).
     - **Low Susceptibility ($< 0.44$):** $210,505$ persons ($2.31\%$).
  2. Summing **Very High** and **High** alone:
     $$6,027,704 + 2,225,020 = 8,252,724 \text{ persons} \quad (90.43\% \text{ of basin baseline})$$
  3. Moderate susceptibility ($663,126$) is **NOT** included in the $8,252,724$ figure. If Moderate were included, the total would be $8,915,850$ ($97.69\%$).
  4. The unclipped rectangular raster bounding box sum is $11,112,918$ persons, which includes adjacent upland areas and maritime buffers beyond the 21 mandals.
- **Evidence File Paths:**
  - `docs/FINAL_APPLICATION_AUDIT.md` (Lines 54–68)
  - `docs/evidence_reconciliation.md` (Lines 108–137)
  - `scripts/audit_population_exposure.py` (Lines 40–98)
- **Status:** `FAIL` (Original claim included Moderate) / `RECONCILED` (Now corrected to Very High + High only).
- **Corrected Interpretation:**
  The authoritative study-area baseline is **$9,126,353$ persons**. The figure **$8,252,724$ persons ($90.43\%$)** represents resident population residing strictly in **Very High and High** susceptibility zones.
  - **Potential Exposure:** Represents individuals living within areas where topography, river proximity, and land cover create high intrinsic vulnerability to flooding.
  - **Confirmed Affected Population:** Refers exclusively to individuals whose homes or livelihoods were confirmed inundated during a specific flood crest, requiring real-time depth modeling or post-disaster field enumeration. PRAVAH 360 measures potential exposure, not confirmed victims.

  1. File: `backend/app/services/live_alert_ingestion_service.py`, lines 24–26, 115–123.
  2. Actual HTTP request URL:
     `SACHET_GEOJSON_URL = "https://apsdmagis.ap.gov.in/weather-watch/data/cyclone/layers/sachet_alerted_mandals.geojson"`
  3. The service does not connect directly to `sachet.ndma.gov.in`. It connects to the state GIS server operated by the **Andhra Pradesh State Disaster Management Authority (APSDMA)** (`apsdmagis.ap.gov.in`), which publishes SACHET-format cyclone and weather alerts.
  4. Ingested features carry `"senders": "NDMA SACHET / IMD"` or `"APSDMA"`.
  5. The URL `https://sachet.ndma.gov.in/` is stored in the alert object as the public reference `source_url`, but is not the polled API endpoint.
  6. Polling cache TTL is 900 seconds (15 minutes); retrieval timestamp (`retrieved_at`) is logged at each fetch; bulletin publication time (`issued_at`) is extracted from feed properties.
  7. If the upstream server is down, the service loads from `data/monitoring/live_disaster_alerts.json` with `is_cached: true` and flags freshness as `STALE` or `EXPIRED`.
- **Evidence File Paths:**
  - `backend/app/services/live_alert_ingestion_service.py` (Lines 24–26, 99–130, 196–216)
  - `data/monitoring/live_disaster_alerts.json` (Lines 1–120)
- **Status:** `PARTIAL` (Alert pipeline and caching verified; endpoint attribution refined).
- **Corrected Interpretation:**
  PRAVAH 360 ingests official disaster warnings by polling the **APSDMA State GIS Server** (`apsdmagis.ap.gov.in`), which aggregates and mirrors NDMA SACHET and IMD public alerts for Andhra Pradesh mandals. The system records publication time, retrieval time, and expiry time, enforcing a strict 4-state lifecycle (`LIVE`, `STALE`, `EXPIRED`, `UNAVAILABLE`) with 15-minute polling caching.

### 2.6 Item 6: Sentinel-1 Historical Reconstruction Reality

- **Original Claim:**
  > *"Sentinel-1 SAR Track 129 Descending (2022-07-16 00:30 UTC): 4 raw tiles (5.74 GB)... pre-flood baseline SAR GeoTIFF imagery is not downloaded locally... ground-truthed against CWC river gauge records."*
- **Verified Implementation Evidence:**
  1. File audit in `data/processed/sentinel1/`:
     - `track129_20220716/`: Contains 4 raw GeoTIFF tiles totaling $5.74\text{ GB}$ ($1.76\text{ GB}, 1.32\text{ GB}, 1.48\text{ GB}, 1.18\text{ GB}$) acquired 2022-07-16.
     - `track129_water_classification.tif` ($763.8\text{ KB}$): 50m binary water classification derived via adaptive Otsu thresholding.
     - `track129_flood_water_candidates.geojson` ($9.71\text{ MB}$): Vectorized candidate flood water polygons.
     - `coverage_track92_mandals.geojson` and `mandals_track92_coverage_status.geojson`: Only vector boundary footprints. **Zero Track 92 raster files exist on disk.**
  2. Acquisition Pass Directions:
     - Track 129 is an **Ascending pass** (evening acquisition, ~18:14 IST / 12:44 UTC).
     - Track 92 is a **Descending pass** (morning acquisition, ~06:00 IST / 00:30 UTC).
     - They have opposing look directions (east-looking vs west-looking) and different incidence angle profiles. Cross-track differential change detection ($\Delta\sigma_0 = \sigma_{0,\text{T129}} - \sigma_{0,\text{T92}}$) is physically invalid due to radar foreshortening, layover, and viewing geometry mismatches.
  3. Ground-Truth Validation Reality:
     - `scripts/extract_sentinel1_water.py` uses single-date adaptive Otsu thresholding on Track 129 with ESA WorldCover Class 80 (permanent water) and DEM slope (>7°) masking.
     - The candidate floodwater polygons have **not** been validated against independent cadastral field surveys, UAV imagery, or RTK-GNSS high-water marks (which remain restricted state records). They represent satellite-derived candidate water extents.
  4. Physical Radar Limitations:
     - *Canopy double-bounce:* Dense coconut groves and mangrove swamps in Konaseema cause radar double-bounce scattering (bright returns), hiding floodwaters beneath tree canopies.
     - *Wind roughening:* Strong monsoon winds on open water increase backscatter, causing water to appear non-specular.
     - *Paddy saturation:* Irrigated rice paddies produce low backscatter that can be misclassified as floodwater.
     - *Orbital repeat latency:* Sentinel-1A operated alone in July 2022 with a 12-day repeat cycle; fast flood surges occurring between cycles cannot be observed at peak crest.
- **Evidence File Paths:**
  - `data/processed/sentinel1/track129_20220716/` (Physical GeoTIFF tiles)
  - `data/processed/sentinel1/track129_water_classification.tif`
  - `data/processed/sentinel1/track129_flood_water_candidates.geojson`
  - `scripts/extract_sentinel1_water.py` (Lines 1–80)
  - `data/reference/historical_flood_events_godavari.json` (Line 162)
- **Status:** `PASS` (Reconciliation confirms physical files and establishes exact geometric/physical constraints).
- **Corrected Interpretation:**
  Track 129 raw peak flood tiles ($5.74\text{ GB}$) and derived 50m water candidate polygons ($9.71\text{ MB}$) are physically stored and verified on disk. Track 92 pre-flood baseline rasters are absent locally. True dual-date differential change detection requires acquiring a matching **Ascending Track 129 pre-flood baseline**. The flood candidate polygons are remote sensing inferences, not cadastral ground-truth survey records.

5. **Alert Ingestion Documented:** Alerts are ingested from the **APSDMA state GIS mirror** with 15-minute polling caching and full temporal lifecycle tracking.
6. **SAR Capabilities Bounded:** Track 129 floodwater candidates ($9.71\text{ MB}$) represent single-date Otsu-thresholded remote sensing inferences; dual-date change detection is pending matching Ascending Track 129 baseline rasters.
